## Scenario L44228-C

Source-supported context: vulnerable log4j-core versions can process attacker-controlled JNDI input and permit remote code execution. The frozen October 28 KEV snapshot includes this CVE, with dateAdded 2021-12-10.

Analytical assumptions: a self-managed, internet-facing Linux web application uses Java 8 and log4j-core 2.14.1, logs attacker-controlled input, and permits the outbound communication needed for the assumed exploit. Successful code execution has occurred as the application service account. Configuration files and application secrets readable by that account may therefore be exposed. These are case assumptions, not observations from an incident.

Root access, domain compromise, encryption, VMware Horizon and OT/ICS deployments are excluded. Persistence, actual secret theft, exposure duration, other affected assets and available telemetry remain unknown. E4 is relevant because potentially exposed application identities need assessment; credential theft is not asserted.

## Interpretation and disputed boundaries

The joint advisory separates asset remediation from investigation. A later fixed state does not establish an asset’s earlier history; the advisory specifically raises the possibility of attacker-applied patches. A mitigation scan therefore supports E6, without independently resolving the compromise response.

L04’s instruction to initiate incident response receives only broad E5 actionability credit. It does not supply an eradication, rebuild or restoration procedure. This boundary should be checked during recoding; a stricter recovery-only interpretation would change that pair from 1/0 to 0/0. Other categories are unchanged by that alternative.

The Canadian alert retains superseded advice alongside updates. Its withdrawal of the formatMsgNoLookups mitigation must be read with the earlier text. Its update 7 version strings also require checking against Apache before any operational use. The source is preserved as written; questionable strings are not silently corrected.

E7 remains zero in this three-document pass. Requirements for mitigation verification, monitoring and reporting do not explicitly establish disposition of the whole compromise response. Pending linked incident-response guidance could change that observation. This is not a completed CVE-level closure finding.
